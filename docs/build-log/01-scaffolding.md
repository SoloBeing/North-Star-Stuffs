## Decisions made, and why

### 1. Form templates live in the frontend, not the backend

The spec says offline is non-negotiable. If the 10 template JSONs were fetched
from the API, the app would be dead on a phone with no signal. So they are
**bundled into the JavaScript build** and cached by the service worker.

The backend therefore only keeps what a browser genuinely *cannot* do:

- DigiLocker token exchange — needs the client secret, which must never ship to a browser
- The V1 Gemini call for unknown forms

This is not a departure from the spec's React + FastAPI stack. It is that stack,
with the split drawn where offline capability forces it.

### 2. Tailwind v4, configured through Vite

Tailwind v4 uses a Vite plugin and a `@theme` block in CSS. There is no
`tailwind.config.js` and no `postcss.config.js` any more — if you follow an older
tutorial that tells you to create those, ignore it.

### 3. Design tokens are set for our actual users

Our users are elderly, often low-literacy, usually on a cheap phone in daylight.
`src/index.css` encodes that:

| Token | Value | Reason |
|---|---|---|
| body font-size | 18px | The spec's accessibility floor. Never go below this |
| `--text-*` scale | 18 / 20 / 24 / 30 / 36 px | Starts *at* the floor, not below it |
| Colours | High-contrast only | Readable in sunlight on a cheap LCD |
| `:focus-visible` | 3px solid ring | Shared keyboard-attached devices at a CSC |
| `prefers-reduced-motion` | animations disabled | Accessibility |

Two animations are defined: `.fm-listening` (pulsing ring while the mic is open)
and `.fm-rise` (screen entrance).

### 4. PWA service worker

`vite-plugin-pwa` with `registerType: 'autoUpdate'`. Two settings matter:

- `maximumFileSizeToCacheInBytes: 12MB` — the default is 2MB, which would have
  silently refused to cache Tesseract's OCR model and broken offline OCR.
- A `CacheFirst` runtime rule for Tesseract's model CDN, so the ~4MB language
  model survives to the second visit.

`devOptions.enabled: false` — the service worker is **off in `npm run dev`**.
To test offline behaviour you must build and preview (see below).

### 5. Dev proxy

`vite.config.js` proxies `/api` to `127.0.0.1:8000`. Everything is same-origin in
development, so there are no CORS errors to debug while building.

### 6. App icons

No image tooling (ImageMagick, Inkscape, rsvg) is installed on this machine, so
the PNG icons were generated by a small pure-Python script — a blue rounded
square holding a white form sheet with a saffron mic badge. `favicon.svg` is the
same design hand-written as SVG.

If you want to redesign the icon, just replace
`frontend/public/icon-192.png` and `icon-512.png` with any 192px and 512px PNGs.

## How to run it

```bash
# Terminal 1 — API
uv run main.py                    # http://127.0.0.1:8000

# Terminal 2 — app
cd frontend && npm run dev        # http://127.0.0.1:5173
```

To test **offline mode** (service worker is disabled in dev):

```bash
cd frontend
npm run build && npm run preview
# open the preview URL, load it once, then switch off Wi-Fi and reload
```
